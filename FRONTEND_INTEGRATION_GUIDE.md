# Person 5 dashboard handoff

1. Install Person 4 requirements and Person 2 requirements into `.venv` (see README). For offline MOCK work, run `.venv\Scripts\python.exe -m uvicorn api.main:app --port 8000` with service URL variables unset. To launch actual Person 1 and 2 APIs, run `powershell -ExecutionPolicy Bypass -File scripts\start_integrated.ps1` from the project root. Person 2's real mode may need NASA network access and downloaded LOLA/SPICE data.
2. Set dashboard backend URL to `http://127.0.0.1:8000`. For Vite, allow `http://localhost:5173` (default CORS); set `LUNA_CORS_ORIGINS` for another origin.
3. POST a mission using `examples/demo_request.json` to `/mission/plan`. Show a loading state while waiting; visibility analysis may take seconds per site/date. Handle 422 input errors and 502 service errors separately.
4. Show `ranked_alternatives` as the ordered list and `candidates` for feasible/rejected detail. Plot `site.latitude_deg` and `site.longitude_deg` as Moon pins. Convert longitude above 180 to negative degrees if the map needs `[-180,180)`.
5. Display `visibility.sunlight_hours`, `earth_visible_hours`, `max_blackout_hours`, optional `route.distance_m`, `score`, `explanation`, `violations`, `warnings`, and `limitations`. Badge each measurement using its own `provenance.status`. Never label MOCK or UNVERIFIED as NASA verified.
6. Replan by POSTing the previous full `PlanResponse` and changed `Requirements` to `/mission/replan`. Show a no-results state when `recommendation` is null.
7. Use `/mission/compare` for baseline/hybrid inspection. The runtime figures are per-request observations, not evidence that one method is superior.

The supplied clean Person 3 archive includes Moon Explorer source. The handoff ZIP contains its `src/web`, `src/shared`, fixtures, package metadata and Vite configuration under `original_modules/person3/moon_navigation/`. It is a separate UI component that Person 5 can run or embed; its API target defaults to `http://localhost:3003` through the Vite proxy. Install its dependencies with `pnpm install --no-frozen-lockfile`, then `pnpm approve-builds esbuild`; run `pnpm dev:web` for the map. Its `pnpm typecheck`, 30 Vitest tests, and `pnpm build:web` pass with the integration dependency fix. `FRONTEND_DATA_EXAMPLES/` contains schema-valid mock UI states. `openapi.json` is exported from the actual FastAPI app.
